# 개발일지 2026-08-25

## 작업 환경
- 마이오노트 (Next.js 16 App Router + Supabase) / Vercel 서버리스 (`myonote.app`)
- 개발 세션 모델: Claude Sonnet 5
- AI 모델 = Solar/Upstage (Claude 아님)

> 실제 병원 방문 피드백 기반으로 **비즈니스 모델을 병원(원장) 중심 B2B2C로 전환**하기로 결정 — 진짜 페이어(원장)와 진짜 입력 주체(무료 사용자인 부모)가 어긋난 게 근본 문제였음. 이번 세션은 그 첫 단계: DB 기반 + 병원 포털 골격 + 검사입력~병원연결 자동화(위치 기반)까지 구현.

## 0. 방향 전환 요지 (상세 플랜은 세션 내 plan 파일)
1. 1차 데이터(안축장 등) 입력 주체를 부모 → **병원 스태프**로 이동. 단, 스태프 전용 입력 화면은 만들지 않고 **방문 시 부모 폰을 빌려 기존 부모용 검사입력 화면을 그대로 사용**하는 쪽으로 설계 — 코드 중복 없음, 검증된 폼(OCR·SER 계산) 재사용.
2. 병원-환자 연결/전환("타병원 이탈") 감지는 **위치 기반이 1차**: 검사 저장 시점 GPS를 등록된 병원 좌표와 대조해 자동 연결·전환. QR은 최초 온보딩/위치 권한 거부 시 보조 경로.
3. 이탈 시 목적지 병원명은 비공개(추후 유료 기능 검토 대상, 이번 스코프 아님). 결제 연동도 이번엔 제외 — 구조만.

## 1. DB 스키마 — 병원 포털 기반 (`docs/sql/2026-08-25-hospital-portal.sql`)
신규 테이블 3개, 기존 테이블 컬럼 1개 추가, RPC 8개. 기존 `is_guardian()` SECURITY DEFINER 패턴을 그대로 따름.
- `eyebody_hospitals`(name/logo_url/brand_color/notice/**lat·lng**/**connect_token**), `eyebody_hospital_staff`(hospital_id·user_id·role), `eyebody_hospital_patients`(활성 연결은 자녀당 **최대 1개** — 부분 유니크 인덱스 `where superseded_at is null`. 새 병원 연결 시 이전 연결은 자동 `superseded_at` 처리 = 이탈 감지의 핵심 메커니즘).
- `eyebody_exam_records.entered_by_hospital_id` 추가(위치 매칭 결과만 남김, 원좌표는 저장 안 함).
- RPC: `is_hospital_staff`/`my_hospital_id`(권한 헬퍼) · `resolve_hospital_by_location`(반경 200m 매칭, haversine) · `link_child_to_hospital`(연결/전환 공용) · `connect_child_to_hospital`(QR 토큰 경유, 내부적으로 위와 동일 함수 재사용) · `get_my_hospital`(부모용 브랜딩 조회) · `hospital_overdue_patients`(재방문 필요 + 이탈 리스트) · `hospital_patient_roster`(환자 목록).
- **버그 1건**: `RETURNS TABLE(...)`인 plpgsql 함수 안에서 리턴 컬럼명과 같은 이름의 테이블 컬럼을 서브쿼리에서 비한정 참조 → `column reference ... is ambiguous`(`next_appointment`, `child_id`). 원장 대시보드가 무한 로딩에 빠지는 걸로 실사용 중 발견, Supabase 로그(`query_logs`)로 원인 특정 후 즉시 패치(별칭으로 회피). 이 패턴은 메모리에 기록해둠 — 앞으로 같은 실수 방지.

## 2. 원장 포털 골격 (`/clinic/*`)
- `/clinic/login`(이메일/비밀번호, 카카오 로그인 쓰는 부모 앱과 분리) · `/clinic`(재방문 필요 + 이탈 리스트) · `/clinic/patients`(로스터) · `/clinic/settings`(QR 코드 표시 + 재발급).
- 인증 보호는 기존 `/dashboard`(`DashboardShell`)와 동일하게 **클라이언트 컴포넌트에서 세션·역할 체크**(`ClinicShell`) — 이 Next 버전은 `middleware.ts`가 `proxy.ts`로 이름이 바뀌었고 레포에 둘 다 없어서(기존 `lib/supabase/middleware.ts`는 실제로는 아무 데도 연결 안 된 죽은 코드) 애초에 서버 미들웨어 방식 보호가 동작하지 않던 상태 — 새 기능도 기존 관행 그대로 따름(별도 이슈로 남겨둠, 이번 스코프 아님).
- `HospitalContext`(`ChildContext`와 동일 패턴), 병원 관련 쿼리 함수는 기존 `lib/supabase/queries.ts`에 섹션 추가(신규 파일 안 만듦).
- 운영자용 테스트 병원("테스트안과") + 스태프 계정 1개 만들어 실기기 로그인→대시보드 노출까지 확인.

## 3. 검사입력 → 병원 자동 연결 + 즉시 알림
- `lib/geo.ts`(위치 획득, best-effort — 실패해도 기존 자가입력 흐름 그대로 유지).
- `/dashboard/records`에서 **신규** 검사 저장 성공 직후(수정은 제외) 위치 캡처 → `resolve_hospital_by_location` → 매칭되면 `link_child_to_hospital` 자동 호출 + `/api/exam-notify`로 보호자 즉시 푸시.
- 웹푸시 발송 로직을 `lib/server/push.ts`로 추출해 **`/api/push/cron`(기존 예약 리마인더)과 신규 `/api/exam-notify`가 공용**(중복 제거, 크론 라우트 리팩터).
- `/connect/[token]`(QR 보조 경로) + 로그인 왕복 후 원래 페이지로 복귀하는 `mn_post_login_redirect` localStorage 패턴(`/auth/callback`).
- 신규 의존성 `qrcode`(순수 JS, `/clinic/settings`에서 QR 이미지 렌더).
