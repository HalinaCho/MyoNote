## 0. 이번 세션을 관통한 두 가지 판단

### "환자가 화면을 같이 본다"
원장이 진료 중 안축장 그래프를 공유화면에 띄워 설명하겠다는 요구에서 시작했는데, 곧 **다른 환자 정보와 병원 경영 지표가 그 화면에 같이 있으면 안 된다**는 제약으로 이어졌다. 재방문 필요·이탈됨 목록은 다른 환자의 이름과 이탈 사실을 드러내고, 통계 카드는 병원 내부 숫자다.

처음엔 헤더에 전역 환자 검색을 달아 "진료 중엔 이 경로만" 쓰자고 제안했는데, 사용자가 더 나은 안을 냈다: **환자 탭 자체를 진료용 화면으로 정의**하고 전체 목록을 한 단계 안으로 밀어넣기. 채택.

- `/clinic/patients` = 진료용. 검색창만 있고 **선택 전에는 어떤 환자 정보도 그리지 않는다**. 이름을 골라야 그 아래 틀에 데이터가 채워진다(`?child=id`로 상태 유지 — 새로고침·뒤로가기 정상 동작)
- `/clinic/patients/all` = 전체 목록 + 재방문 필요/이탈됨 카드. 원장이 혼자 볼 때만 들어가는 화면
- 대시보드(홈)도 같은 이유로 "진료 전/사이에 혼자 보는 화면"으로 성격을 못박음

### 순응도는 병원 포털의 지표가 아니다
사용자 판단: **부모 자가입력이라 신뢰도가 낮다.** 홈 통계 후보로 "평균 순응도"를 제안했다가 거절당했고, 환자 진료 화면의 순응도 박스도 뺐다. 대신 활동량 지표로 **"우리 병원이 직접 입력한 검사 건수"**를 쓴다 — 스태프가 병원에서 넣은 데이터라 신뢰도가 다르다. (전체 목록 화면의 7/30일 컬럼은 기존 기능이라 유지)

## 1. 환자 탭 재구성 (`24d1e23`)

- `/clinic/patients/[childId]` 라우트 삭제 → 검색 화면에 흡수. 진료 중 화면 전환이 한 번 줄었다
- 최근 검색을 `{이름, id}` 쌍으로 저장 — 검색어 문자열만 남기던 기존 방식과 달리 **클릭 한 번에 그 환자로 점프**
- 그래프는 부모 앱의 `TrendView`/`PctView`에 `export`만 붙여 그대로 재사용. 차트 로직을 병원용으로 새로 만들지 않았다
- Next 16 `react-hooks/set-state-in-effect` 대응: 상세 데이터를 `{childId, data}`로 담고 **파생값으로 읽는다**. 환자를 바꾸는 순간 이전 데이터가 자동으로 무효가 돼서, effect에서 `setDetail(null)`을 호출할 필요 자체가 사라진다

## 2. 웹 폭 최적화 (`e9b7607`) — 그리고 그게 만든 버그

포털 컨테이너가 부모 앱과 같은 `max-w-3xl`(768px)이라 진료실 PC 화면을 못 쓰고 있었다. `max-w-6xl`로 넓히고 환자 상세를 2×2 그리드로.

그런데 **좌측에 큰 공백**이 생겼다. 원인은 `PctView`가 조각(fragment)으로 카드 3개(백분위 그래프·최근 검사 기준·각주)를 한꺼번에 내보내는데, **fragment는 DOM 요소가 아니라서 그리드가 그 3개를 각각 별도 칸에 흩어 놓은 것**. 각주가 왼쪽 칸에 혼자 떨어지고 위아래가 비었다.

→ 3번에서 **열별 스택**(`flex` 2열, 각 열이 자기 카드를 세로로 쌓음)으로 바꿔 해결. 카드 높이가 서로 안 묶이니 빈칸이 생길 수 없다.

## 3. 대시보드 신설 (`3b11639`)
SQL: `docs/sql/2026-09-03-clinic-dashboard.sql`

참고한 B2B 분석 대시보드 형태에 맞춰 셸부터 다시.

- **셸**: 상단 탭 4개 → 좌측 사이드바(병원 로고·이름 + 대시보드/환자/소식/설정 + 로그아웃). 좁은 화면에서는 같은 마크업이 상단 바로 접힌다(반응형 클래스만으로, 마크업 이중화 없음)
- **KPI 5종**: 총 환자 / 이번달 신규 연결 / 이번달 검사 입력 / 재방문 필요 / 이탈됨. 신규·검사는 **전월 대비 증감**을 같이 보여준다
- **위젯 4종**
  - **진행 위험도 분포** — 도넛(안정/주의/진행/판정불가) + 진행이 빠른 환자 Top 5(클릭하면 그 환자 화면으로). 이 제품에서만 나올 수 있는 위젯이고, 원장이 돈을 낼 이유에 가장 가깝다
  - 월별 검사 입력 추이 / 신규 연결·이탈 추이 / 치료별 환자 분포
- **위험도 판정을 SQL에 넣지 않았다.** `hospital_patient_summary`는 최근 24개월 안축장 원자료만 주고, 연간 성장률은 부모 앱과 같은 `axialGrowth`를 클라이언트에서 돌린다. SQL로 옮기면 같은 숫자를 두 벌로 유지하게 되고, 언젠가 갈린다
- **진행 예측 재사용**: `buildForecast`가 `Child` 대신 `birth`를, `ExamRecord[]` 대신 최소 필드(`ForecastExam`)를 받도록 바꿔 포털에서도 같은 카드를 쓴다. `ForecastCard`는 컨텍스트를 읽는 얇은 껍데기 + 데이터만 받는 `ForecastView`로 분리

## 4. "조회에 실패했습니다"만 뜨던 문제 (`95b640a`)

SQL 적용 후에도 대시보드가 빨간 한 줄만 보여줬다. Supabase MCP로 DB를 직접 들여다보니 **새 함수 2개가 아예 없었다** — 사용자가 같은 날 먼저 만든 `2026-09-03-clinic-home-stats.sql`(옛 파일)을 실행한 것이었다.

원인은 두 겹이었고 둘 다 고쳤다.
1. **에러 사유가 화면에서 사라졌다.** Supabase 에러(`PostgrestError`)는 `Error` 인스턴스가 아니라서, 코드베이스 전반에 있는 `err instanceof Error ? err.message : '조회에 실패했습니다'` 패턴이 `"Could not find the function public.hospital_monthly_stats"`라는 정확한 사유를 통째로 삼켰다 → `errMessage()` 헬퍼로 어떤 모양이든 사유를 꺼내 보여준다(포털 화면부터 적용)
2. **옛 SQL 파일이 함정이었다.** 그 파일을 실행하면 전월 대비 값이 없는 옛 `hospital_home_stats`로 조용히 되돌아간다 → 파일을 삭제하고, 대체 파일 머리말에 그 사실을 적었다

새 SQL 자체는 적용 전에 MCP 읽기 쿼리로 실제 데이터에 돌려 검증했다(월별 12개월 채움, 환자 요약 반환 확인).

## 5. 소식 탭 웹 개편 (`06fe50d`)
SQL: `docs/sql/2026-09-03-post-schedule.sql`

- **목록 3열 컬럼(masonry)** — 카드 높이가 제각각이라 그리드로 묶으면 또 빈칸이 생긴다. `columns` + `break-inside-avoid`로 위에서부터 채운다
- **폰 미리보기**: 작성 폼 우측에 390px 프레임으로 보호자 앱에서 보이는 모습을 실시간 표시. 기존 `PostView`를 그대로 써서 "원장이 보는 모습 = 부모가 보는 모습"이 코드 한 벌로 유지된다
- **노출 배지 3종**: `보호자 홈에 노출 중`(발행된 것 중 최신 3개) / `예약` / `지난 소식`. 홈에 3개만 보인다는 규칙이 목록에서 안 보이던 문제
- **예약 발행**: `publish_at` 컬럼 추가, `hospital_feed`가 `publish_at <= now()`만 내려준다. 표시 날짜도 `created_at`이 아니라 `publish_at` — 미리 써둔 글이 "2주 전 소식"으로 보이면 안 된다. **기존 글을 수정할 땐 원래 발행 시각을 지킨다**(오타 하나 고쳤다고 목록 맨 위로 올라오면 안 되니까)
- 사진 **끌어다 놓기 · Ctrl+V 붙여넣기**
- **임시저장**: 새 글의 본문·링크만 localStorage에. 사진(dataUrl)까지 넣으면 브라우저 저장소 한도(약 5MB)를 금방 넘겨 저장 자체가 실패하므로 제외하고, 불러올 때 "사진은 다시 골라주세요"라고 알린다

## 0. 운영 방식 — 제안 먼저, 구현은 고른 뒤에

에이전트를 둘로 나눠 병렬로 돌렸다(부모 앱 / 병원 포털). 다만 **디자인이 걸린 작업은 코드를 못 쓰게 하고 안 2~3개 + ASCII 목업만 받았다.** 사용자가 고른 뒤에 한 번에 구현.

이게 실제로 값을 했다. 검사 모달은 "안축장·나안시력 모두 필수 + 좌우바꾸기 삭제"가 이미 확정돼 있었지만, 레이아웃 안이 정해지기 전에 구현했으면 같은 JSX를 두 번 고쳤을 것이다. 실제로 사용자는 안을 고르면서 **필수 범위를 안축장만으로 번복**했다 — 먼저 구현했으면 그것도 다시 뜯었어야 했다.

## 1. 원장 포털 설정 화면 (`d3af429`)

1부의 숙제. 이 화면만 옛 모바일 폭 한 줄 컬럼이라 사이드바 셸과 안 맞았다. 소식 탭과 **같은 "좌: 편집 / 우: 미리보기" 배치**로 통일 — 왼쪽에 병원 정보·브랜딩, 오른쪽 340px 고정폭에 보호자 앱 홈 미리보기와 QR.

가로로 늘어나던 저장 버튼을 데스크톱에선 내용 폭으로 줄이고 전체를 `max-w-5xl`로 잡았다. 넓은 화면에서 버튼 하나가 1200px로 뻗는 건 웹 도구로 보이지 않는다.

## 2. 검사 기록에 나안시력 (`66dcc7f`)
SQL: `docs/sql/2026-09-03-exam-visual-acuity.sql` (적용됨)

나안시력 우/좌 2칸, 소수시력 직접 입력(0.01~2.0, 선택). 범위 밖은 저장 시 토스트로 막고 **DB에도 같은 제약**을 걸었다 — 오타 하나가 그래프를 망치는 걸 앱 한 겹으로만 막지 않는다.

읽기 경로에서 컬럼 열거를 `select('*')`로 바꿨다. 마이그레이션 전에 배포되면 없는 컬럼 하나 때문에 **검사 탭 조회 전체가 실패**한다 — `*`면 없는 컬럼이 `undefined`로 와서 빈 값으로 표시될 뿐이다.

## 3. 검사 입력 모달을 측정값 통합 표로 (`98b6c52`)

항목마다 "우안(OD) [ ] 좌안(OS) [ ]"가 반복돼 모달이 길고 지루했다. 우안/좌안을 **맨 위 열 헤더로 한 번만** 쓰고 항목을 행으로 두는 표 하나로 합쳤다(굴절값도 같은 그리드를 이어 쓴다). 측정 영역 세로 224px → 142px.

- **안축장만 필수**로. 사용자가 처음엔 나안시력도 필수라고 했다가 안을 고르면서 번복
- **좌우 바꾸기 버튼 삭제.** OCR이 눈을 뒤바꿔 읽는 걸 되돌리는 버튼이었는데, 좌우 값이 같은 행에 나란히 놓이면서 **레이아웃이 그 역할을 대신한다**
- 시각 라벨이 열 헤더로 올라가면서 스크린리더가 칸을 못 읽게 됐다 → 입력칸 8개 전부 `aria-label`. 쓰이지도 않던 `placeholder` prop을 `ariaLabel`로 교체
- 순 −15줄. 반복을 없앴더니 코드가 줄었다

폐기 대상이던 걱정 하나는 DB로 확인해 걷어냈다: "안축장 빈 옛 기록은 이제 수정 저장이 막힌다" → 검사 기록 35건 전부 안축장이 채워져 있어 해당 없음.

## 4. 병원 브랜드 컬러 (`0ce86c7`, 그리고 `e42d694`로 절반 되돌림)

원장이 브랜드 컬러를 고르면 부모 홈의 **로고 둘레 2px 테두리**에만 적용되고 있었는데, 사용자가 "안 어울린다"고 했다.

코드를 읽다가 **과거에 두 번 실패한 기록이 주석에 남아 있는 걸 발견했다** — ①카드 전체를 색면으로("어떤 색이든 덩어리로 튀었다") ②상단 4px 선("둥근 모서리에 사각형 선이 잘려 보였다"). 그래서 링만 남은 것이었다. 새 안은 이 둘을 반복하지 않는 방향으로만 짰다.

채택안: **새 색면을 더하지 않고, 원래 teal이 칠해져 있던 자리를 병원 색으로 갈아끼운다.** 하드한 2px 선 → 로고 뒤 옅은 원(후광).

대비 처리가 이번 작업의 핵심이었다. 원장이 형광 노랑이나 연회색을 고를 수 있다.
- `onWhite()` — RGB를 같은 비율로 낮춰 **색상은 유지한 채** 명도만 떨어뜨린다. 형광 노랑 `#facc15` → `#856c0b`(대비 4.79). 회색으로 뭉개지지 않는다
- 두 번째 인자를 "배경 밝기 상수"가 아니라 **틴트의 알파**로 받는다. 짙은 남색은 12% 틴트 배경이 실제로 0.75까지 어두워져서, 고정 밝기로 계산하면 대비가 4.5:1 아래로 떨어진다
- `brand_color`가 DB에 자유 텍스트라 검증 없이 CSS에 꽂히고 있었다 → 형식이 깨지면 기본색 폴백
- **자체검사를 남겼다**(`src/lib/utils/color.check.mts`). 대비 계산은 눈으로 검증이 안 되는 로직이다. 7색 × (흰 배경 / 12% 틴트 위) 4.5:1, 잘못된 값 6종 폴백, 대비 계산을 독립 재구현해 교차검증. `node src/lib/utils/color.check.mts`

곁다리로 두 개 더 고쳤다: 설정 미리보기의 폰 배경이 회색이라 **실제 부모 홈 배경(`#edf7f6`)과 달랐다**(원장이 실제와 다른 배경 위에서 색을 고르고 있었다), 그리고 위의 색값 검증.

**그리고 절반을 되돌렸다** (`e42d694`) — 사용자가 D-day 배지에 병원 색 쓰는 걸 취소. **예약일은 병원이 아니라 앱이 관리하는 정보**라 앱 색으로 둔다는 판단. 병원 색은 로고 자리에만 남는다.

## 5. 다음 예약일을 검사 기록에서 떼어냄 (`f45043c`)
SQL: `docs/sql/2026-09-03-child-next-appointment.sql`(배포 전) → `2026-09-03-drop-exam-next-appointment.sql`(배포 후). 둘 다 적용됨

사용자가 준 이유가 정확했다: **검사값을 저장하는 시점(검안실)과 다음 예약을 정하는 시점(데스크 수납)이 다르다.** 시점이 다른 두 정보가 한 폼에 묶여 있었다.

코드를 읽어보니 홈에는 **이미 예약일 편집 UI가 있었다.** 빠진 건 "예약이 하나도 없을 때의 진입점" 하나뿐 — 편집 UI와 표시가 전부 `nextAppt &&` 조건 안에 있어서, 예약이 없으면 홈에서 넣을 방법이 없고 그래서 검사 모달이 유일한 최초 입력 경로가 됐던 것이다. **불편의 원인은 기능 부재가 아니라 조건 하나였다.**

구조도 같이 바로잡았다. 예약일이 검사 기록마다 붙어 있어서 ①검사 0건인 아이는 예약을 넣을 곳이 없고 ②부모 홈("오늘 이후 가장 이른 예약")과 원장 포털("가장 최근 검사의 예약일")이 서로 다른 값을 볼 수 있었다. 이제 정본은 `eyebody_children.next_appointment` 하나다.

- 홈: 방문 예정일 줄을 **항상** 렌더. 예약이 없으면 D-day 칩 자리가 `+ 입력` 버튼. 아래로 점프하던 별도 편집 카드는 삭제하고 그 줄에서 인라인 편집
- **"예약일 지우기"는 명시 버튼.** 날짜를 비워서 지우는 방식은 부모가 발견하지 못한다
- 원장 포털 RPC 3개 교체(overdue/roster/detail). **반환 컬럼 이름·타입을 그대로 둬서 화면 코드는 무변경** — 값의 출처만 바뀌었다. `pg_get_functiondef`로 현재 정의를 DB에서 읽어와 바꿀 부분만 고쳤다(이탈 절을 기억으로 재작성하지 않기 위해)
- **예약 D-day 푸시도 같이 고쳐야 했다.** 지시에 없었지만 안 고치면 알림이 통째로 깨진다 — 크론이 검사 기록을 읽고 있었다
- 순 −28줄

## 6. 지난 예약 숨김 + 알림 문구 (`a7b33da`)

지난 예약이 `D+n`으로 계속 떠 있으면 **예약이 잡혀 있다고 착각한다**는 지적. 홈에서는 예약 없음과 똑같이 "아직 정해지지 않았어요"로. **DB 값은 지우지 않는다** — 원장 포털의 "재방문 필요"가 바로 그 지난 예약을 읽는다. 같은 데이터를 두 화면이 반대 목적으로 쓰는 경우다.

알림도 바꿨다. 제목을 **병원명**으로(부모 폰에는 "마이오노트"보다 다니는 병원 이름이 먼저 읽힌다), 본문은 날짜·병원명 대신 **"오늘/내일/N일 뒤 병원 방문일이에요"**.

## 7. 알림 배지 — 네 번 고쳤다 (`d3f1da6` → `20eb30c` → `22781d0` → `b5fdddd`)

이번 세션에서 가장 많이 되돌린 곳이고, 배운 게 가장 많은 곳이다.

1. **통짜 흰 네모가 떴다.** `badge`는 안드로이드가 **알파 채널만 읽어 실루엣으로** 그린다. 배경이 꽉 찬 `icon-192.png`를 쓰고 있었으니 통째로 사각형이 될 수밖에 없었다 → 투명 배경 전용 배지 추가
2. **오른쪽에 회색 "M"이 떴다.** 텍스트 폭을 벌려고 `icon`을 뺐더니, 크롬이 앱 이름 첫 글자로 **모노그램을 자동 생성**했다. 큰 아이콘 자리는 비울 수 없다 → `icon`을 되돌리고, 대신 **병원 로고**를 넣어 왼쪽=앱 / 오른쪽=병원으로 역할을 갈랐다(왼쪽 작은 아이콘은 OS가 그리는 자리라 제어 불가)
3. **배터리처럼 보였다.** 클립보드 실루엣이 "위에 꼭지 달린 채워진 둥근 사각형"이라 정확히 배터리 형태였다 → 눈 모양으로 교체
4. **"우리 로고랑 다른데?"** — 맞는 지적이었다. `public/icon.svg`를 읽지 않고 형태를 새로 그렸다. 실제 로고의 눈은 눈꺼풀 아치 + 속눈썹 5개 + 홍채 링인데 아몬드에 속눈썹 3개로 그렸고 클립보드 비율도 임의였다 → **원본 좌표를 그대로** 쓰고(몸통 266,300 492×576 rx72 / 클립바 398,250 228×98 rx46 / 눈꺼풀 경로 / 속눈썹 5개 위치 / 홍채 반지름), 몸통은 채우지 않고 테두리만 남겨 배터리 오해도 같이 없앴다
5. **작게 보였다.** 배지 크기는 24dp 고정이라 키우려면 PNG 안의 여백을 줄이는 수밖에 없다 → 뷰박스를 도형 외곽에 바짝 붙여 세로 채움 84% → 96%

원본과 다른 건 **획 두께 하나뿐**이다. 원본 속눈썹은 1024 기준 18이라 24px에서 0.4px가 되어 사라진다. 좌표·비율은 두고 두께만 키웠다.

후보 비교는 Claude Design 캔버스로 만들어 사용자가 실제 크기·상태바 맥락에서 고르게 했다.

## 배운 것 (다음에 또 쓸 것)

- **서비스워커 갱신 규칙** — 이미지 파일만 바뀌는 변경(배지 모양)은 파일명이 같으므로 **폰에서 갱신 없이 즉시 반영**된다. `sw.js` 코드가 바뀌는 변경(오른쪽 아이콘을 병원 로고로)은 **폰의 서비스워커가 새로 깔려야** 반영된다. 이걸 몰라서 "배포했는데 왜 그대로냐"를 두 번 왕복했다
- **웹 푸시 구독은 브라우저마다 완전히 별개다.** 삼성 인터넷과 크롬은 서비스워커도 푸시 서버도 따로다. 한쪽에서 갱신해도 다른 쪽은 옛 버전이 남는다. 옛 구독이 살아 있으면 옛 모양 알림이 섞여 온다
- **같은 태그의 알림은 조용히 교체된다** — 트레이에 남은 알림이 갱신될 뿐이라 "안 바뀐 것처럼" 보인다. 확인할 땐 먼저 지우고 받을 것
- **아이콘·에셋은 실제 파일 좌표에서 뽑을 것.** 기억이나 눈대중으로 다시 그리면 반드시 티가 난다
- **되돌리기 기록은 주석에 남길 것.** 브랜드 컬러에서 과거 실패 두 건이 주석에 있어서 같은 실패를 반복하지 않았다

## 결정 — 소개 사이트는 같은 레포·같은 배포에

- **유저가 늘어도 위험도는 안 변한다** — 소개는 정적 CDN이라 앱 서버를 안 건드린다

쪼개면 검색 신뢰도가 갈리고, 루트에 소개 + `/dashboard`에 앱을 두 프로젝트로 구성하려면 주소를 이어붙이는 설정이 필요해 오히려 더 자주 깨진다. 나중에 빼기도 쉬워 락인이 없다.
