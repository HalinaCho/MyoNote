## 1. 푸시 크론 Vercel → Supabase pg_cron 이전 (`00302ac`)
- **문제**: 09:00 KST(=00:00 UTC) 설정인데 실제 알림이 **13시경 도착**(07-03~ 관측). Vercel Hobby 크론은 지정 "시각"이 아니라 시간대 내 임의 시점 실행이며, 실측은 그보다도 늦었음 → 정시성 확보 불가.
- **해결**: 이미 쓰는 Supabase의 **pg_cron + pg_net**이 매일 00:00 UTC에 `/api/push/cron`을 HTTP GET(Bearer `CRON_SECRET`) 호출. 분 단위 정확도, 추가 비용·서비스 없음.
- SQL = `docs/sql/2026-07-07-pg-cron-push.sql` (레포엔 시크릿 플레이스홀더만). 잡 이름 `push-appt-reminder`, 같은 이름 재등록 = 교체라 재실행 안전.
- `vercel.json` 삭제(크론만 있었음 — 이중 발송 방지). 라우트 코드는 주석만 갱신.
- 검증 쿼리: `cron.job`(등록), `cron.job_run_details`(실행 이력), `net._http_response`(응답 200 + `{"ok":true}`).
- ⏭️ 다음 09:00 KST 정각 수신 확인 대기.

## 2. 커스텀 도메인 `myonote.app` 라이브 (`75aac5f`, `8b5b0d7`)
- Vercel에서 구매·연결. RDAP로 가용 확인 후 당일 확보.
- **코드 수정 최소**: `src/`에 도메인 하드코딩 0건(전부 `NEXT_PUBLIC_SITE_URL` 유래, metadataBase/OG 포함) → env 변경 + 재빌드로 끝.
  - 주의: 첫 Redeploy에서 OG가 구 도메인으로 남아있었음 — **빌드 캐시 없이 재빌드**해야 `NEXT_PUBLIC_*` 반영(빈 커밋 푸시로 해결).
- 설정 마이그레이션: Vercel env `NEXT_PUBLIC_SITE_URL=https://myonote.app` / 카카오 사이트 도메인 추가 / Supabase Site URL·Redirect URLs 추가 / `www.` → 308 리다이렉트.
- 검증 완료: 200+SSL/HSTS, `og:url` 신 도메인, www 308, manifest·sw 200, 크론 라우트 401(보안 정상).
- pg_cron 호출 URL도 신 도메인으로 교체(SQL 문서 갱신). 구 `myonote.vercel.app`은 별칭으로 계속 서빙.
- **PWA는 origin 단위** → 기존 설치 유저는 신 도메인에서 재설치+알림 재구독 필요(푸시 endpoint 자체는 도메인 무관). 유저 적은 지금이 전환 적기.
- 부수 효과: `.app`은 HTTPS 강제 TLD. 향후 스토어 등록(TWA)·App Links(카카오로그인 외부브라우저 개선)의 전제 확보.

## 3. 알림 지원 범위 확인 (문서화)
- 앱은 설치 여부가 아니라 **브라우저 푸시 지원 여부**로만 게이팅(`lib/push.ts` 확인).
